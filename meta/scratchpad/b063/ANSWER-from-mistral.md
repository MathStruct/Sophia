# B-063 review (Mistral) — the permission classes of `sophia-mcp`

Scope: defects only — wrong results, a way around a check, panics, missing checks, races, missing tests — in the permission-class change (branch `mistral/b063-review`). Tests written to show findings: `crates/sophia-mcp/tests/review_mistral.rs` (the `Client` helper copied from `tests/stdio.rs`; none of its tests repeat a stdio.rs check).

## Findings

**None verified.** Every check I could trace came back clean. The tests in `review_mistral.rs` pin the gaps stdio.rs does not cover; all are expected to pass. The maintainer should run `cargo test -p sophia-mcp`.

### Suspected / could not fully confirm

1. *rmcp-internal routing* — `~/.cargo/registry/.../rmcp-3.11.0` is outside this session's readable paths, so I could not read `ToolRouter::remove_route` or the `#[tool_handler(router = …)]` expansion directly. What I verified instead: `SophiaServer::open` removes disallowed routes from the router field, `src/sophia_mcp.md` documents that the macro's default would build a fresh full router per request (the bug the attribute fixes, found by `tools_are_listed_by_class`), and `permit` re-checks the class at the top of all four mutating methods (`sophia_mcp.rs`: `edit_text`, `add_text`, `rename_name`, `delete_name`), with the store connection itself opened `SQLITE_OPEN_READ_ONLY` when no flag is given — a third lock. `a_disallowed_tool_is_not_dispatched` tests the observable: a disallowed call must be refused without `permit`'s "started without" message, i.e. the method never ran. *Suspected only in the sense that rmcp's side is trusted from the repo note and the passing stdio tests, not read.*
2. *Server-side parse of query text* — `run_query` calls `sophia_query::prepare_text` in the server process; the memory bound (`RLIMIT_DATA`) covers only the worker's execution, not the server-side parse (the JSON-RPC message is already buffered in the server anyway). Not a permission-class defect; noted for completeness.
3. *Profile writes when a flag is on* — with `--allow-edits` or `--allow-removals`, `Interface::open` writes the built-in rendering profiles if missing (`profiles::ensure_built_ins`). That is a store write beyond the class's tools, but it happens only when a write-capable flag is on, so the requirement "without either flag nothing changes" holds. Not counted as a defect.

## Probes (what was checked, the test, the result)

1. **Write/Remove without its flag (another tool, a parameter, a stored query, another MCP method).** Read `sophia_mcp.rs` end to end: `TOOLS` lists exactly the 10 tool methods with the required classes; the only callers of `Interface::write_text/create_text/rename/delete` in the crate are the four gated methods, each starting with `permit(Class::…)`; `#[tool_handler(router = self.tool_router)]` serves the pruned router. Read tools (`show/list/context/run_stored`) only read. `run_stored` resolves parameters to values only. Test: `a_disallowed_tool_is_not_dispatched`. **No defect** — three locks: route removed, `permit`, read-only connection (`Sqlite::open_read_only`, sqlite.rs ~line 134, no `SCHEMA`/`PRAGMA journal_mode`).
2. **Store untouched without flags (WAL sidecars, profiles, schema).** `Sqlite::open_read_only` skips `init`/`SCHEMA`; `Interface::open_read_only` (sophia_interface.rs:157) skips `ensure_built_ins`; the worker's `serve` (bounded.rs) also opens read-only; `Backend::read` is `transaction()+rollback`. stdio.rs checks only the main file's bytes. Test: `read_only_session_creates_no_sidecar_files` (directory listing, bytes, mtime, after a session that also ran a `query` so the worker opened the store). **No defect found by reading**; the test pins the sidecar gap.
3. **Argument parsing turning a flag on.** `bin/sophia-mcp.rs parse`: flags match only exact strings and take no value; unknown args exit 2; `--max-memory` overflow is `checked_mul`; a flag-like token is either consumed as a value (then the server fails to open the store / fails the u64 parse, flags stay off) or is an unknown argument. Test: `flag_like_arguments_are_refused_not_honoured`. **No defect** (fail-closed).
4. **`run`/`save_query` reaching something other than a bounded read.** `sophia_query::load` → `Prepared::from_record` refuses non-query records (lang check + canonical-form check); the query parser has no raw-SQL dialect (`sql.rs` is a translation target only); `run_bounded` spawns the worker with `RLIMIT_DATA = max_memory` and kills it at deadline+grace; the worker runs `Prepared::run` on a read-only tx, and if the SQL strategy runs, `query_compiled`'s authorizer denies everything but SELECT/reads of `t_*`/`pN` CTEs and denies `load_extension/readfile/writefile/edit` — on a read-only connection. `query` refuses parameterized text; `max_rows` can only lower the cap (`min`). Tests: `run_cannot_execute_a_non_query_definition`, `read_only_server_runs_stored_queries_without_touching_the_store`. **No defect.**
5. **`delete` removes a name only.** `Key::name(path)` is always `Derived("name:…")`, so the MCP tools can only reach the `name:` branch of `Interface::delete/rename/write_text` (edit.rs:419-455); the namespace and settings branches are unreachable from the server; `Store::remove` (logic.rs:325) removes only the `t_name` row. `abs(ns, name)` keeps text-defined names under the namespace; `validate_path` rejects bad segments. Test: `delete_on_a_namespace_path_is_refused`. **No defect.**
6. **Race on the version check.** `Store::update` (logic.rs:257-282) re-checks `name.seq == expected` inside the single immediate write transaction and returns `Conflict` otherwise; `write_text` also pre-checks `text_token`; the `Sqlite` connection is behind a `Mutex`. Test: `concurrent_edits_with_one_version_one_wins` (two `edit` calls with the same version sent back to back; exactly one may succeed). **No defect found by reading.**
7. **TOOLS table vs. actual tools.** The `#[tool_router]` impl has exactly the 10 methods `TOOLS` names, with the required classes; a tool missing from `TOOLS` would be served unconditionally, and `tools_are_listed_by_class` (stdio.rs) asserts the exact listing per flag combination, so a mismatch would fail there. **No defect.**
