#implementation #julia #experiment

> Experiment E-6 on Sophia's side: one function's derivative at two layers, Zygote's program at Julia IR and Enzyme's at LLVM IR, stored with **the objects the store already has**: records of two languages, a fact per derivation, and an annotation that carries the numerical test as `tested` evidence that the two compute the same function. Source: `layers.rs`. Results: [[Semantic Boundary Experiments]] §E-6.
>
> Sources: [[Review 2026-11-19 Codex B-027 (external)]]; [[SPEC-006 Worlds, Artifacts and Evidence]] §5 (trust), §6a (transformations as facts); [[Multi-AST Layering]]; [[AD as a Materialization Case]]; [[derivative]] (E-5's oracle reader and keys); [[layer_programs]] is the oracle ([[derivatives]] for the Zygote half). code: `layers.rs`, `tests/layers.rs`, `examples/julia_layers.rs`

- **`parse_layers`** reads `layer_programs.jl`'s output: the Zygote lines through E-5's `parse_derivatives`, then `enzyme` rows (label, status, times, raw and normalised size and digest, addresses found and named), `point` rows (label, x, both gradients, the reference) and `module` texts. A Float32 as Julia prints it (`0.5f0`, `1.0f-5`, `Inf32`, `NaN32`) is read as an `f32` and widened, not as the decimal it spells. A value that does not read is NaN (x, reference) or missing (a gradient), so its point fails the test rather than vanishing from it.
- **Records** (each a one-member component, id from language, normaliser and bytes, as source records are):
  - a Zygote **piece** (`julia-ir`, kind `derived-piece`, normaliser `sophia-e6/zygote-piece@0`): the text of what Zygote runs at one `_pullback` instance, as E-5 prints it;
  - a Zygote **program** (`julia-ir`, kind `derived-program`, `sophia-e6/zygote-program@0`): its root instance and the sorted (signature, piece kind, piece id) triples; its `refs` are the piece ids, which are in its bytes. Pieces are shared between programs (74 references, 23 pieces);
  - an Enzyme **program** (`llvm-ir`, kind `derived-program`, `sophia-e6/llvm-module@0`): the normalised module text. Nothing parses or prints it: the store holds it as bytes, as it holds source files.
- **Facts** (kind `derived-program`, subject f's definition, by Zygote or Enzyme at its version): the value names the layer, the versions (Julia, the AD packages, LLVM for Enzyme), the mode, the argument type and the program's id; the inputs are the ids of f's closure in the package (E-5's `closure_ids`). This is SPEC-006 §6a's transformation record with the relation implicit (D(f) at a layer). The fact is not the input address: for Zygote, E-5 showed the key must also hold the rule facts (`Rules`); for Enzyme no key was scored.
- **The annotation** (checker `sophia-e6/numerical` 0, subjects the Zygote program and the Enzyme program, input f's id): kind `equivalent-tested`, status `tested`, when at every point both gradients exist and differ by at most `TOLERANCE_ULPS` = 4 units of `eps(T) · max(1, |reference|)`, the reference as printed (rounded to Float64); otherwise kind `equivalent-test-failed`, status `failed`. A NaN, a missing value, a type other than `Float64` or `Float32`, or no points at all is not a pass. The payload is the test itself: the obligation, the tolerance, the reference's method, and every point's x and three values as bit patterns. The kind carries the verdict because the query language sees an annotation's kind, not its status (as [[trust]] does with `checked`). The distance to the reference is recorded in `Agreement` but is not the claim: an ill-conditioned function is far from it in both systems alike.
- **`layer_records`** builds them for one label of the output and the package at a directory (the ledger of [[derivative]] gives f's root ids and closure ids, so f's id is the one `store_module` stores). A gradient is skipped with the reason when it lacks a complete Zygote program, Enzyme refused it, its module text is missing or does not hash (SHA-256, as Julia printed it) to its digest, or f has several methods: which one a gradient starts from is dispatch, which the ids do not say, so the fact would have no right subject. **`store_layers`** writes records, facts and annotations in three transactions; storing again adds nothing.
- **`split_module`** cuts a module into its function definitions (`define … }`) and the rest, to measure what per-function records would share. It is a measurement, not a storage format.

What it does not do: parse, print, check or lower LLVM IR; compute an input address for Enzyme's program (its rule world is EnzymeRules methods and the optimised IR of every callee, Base's included; not scored); store a relation from the Julia-IR program to the LLVM one (they are siblings, both derived from f, not one lowered from the other).
