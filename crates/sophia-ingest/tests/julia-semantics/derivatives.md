#implementation #julia #experiment

> The Julia side of experiment E-5 (rules vs derived derivatives): for each function of a package variant and an argument type, the derived program Zygote builds for its gradient, as the **text of what Zygote runs** at every `_pullback` instance the gradient reaches (its generators' output, a rule, or a hand-written adjoint); and the rule tables (`rrule`, `frule`, `no_rrule`, `no_frule`, `ZygoteRules._pullback`, `ZygoteRules.adjoint`) read from the method table without differentiating anything. Source: `derivatives.jl`.
>
> Sources: Zygote 0.7.18 `src/compiler/interface2.jl` (`_generate_pullback`, `_generate_pullback_via_decomposition`), `src/compiler/chainrules.jl` (`has_chain_rrule`), `src/compiler/emit.jl` (`clear_decompositions!`); ZygoteRules (`@adjoint`); ChainRulesCore 1.26.8; Julia 1.12.7 (`code_typed`, `Base.uncompressed_ast`, `Base._methods_by_ftype`); [[Review 2026-11-19 Codex B-026 (external)]]. code: `derivatives.jl`, `rules/` ([[Rules]]), `src/derivative.rs` ([[derivative]]), `tests/derivatives.rs`, `examples/julia_derivatives.rs` ([[julia_derivatives]])

```sh
# from crates/sophia-ingest/tests/julia-semantics, inside `nix develop` (julia112: Zygote's
# environment `rules/Project.toml` was resolved with Julia 1.12.7)
for v in base rule_g adjoint_g adjoint_g_other nondiff_sq method_g32 edit_unused pirate_g pirate_g_other pirate_sin; do
  a=""; [ $v = base ] && a=rules/variants/rule_g/src/added.jl
  julia112 --project=rules derivatives.jl rules/variants/$v $a
done > rules/truth.tsv          # one process per variant
```

- **Run or included.** Run as a program, the script prints everything (`main`). Included (as [[layer_programs]] does for E-6), it loads the variant from `ARGS[1]` and defines its functions without printing. The in-session part runs in `session`, called through `invokelatest` so that it sees the methods the included file added (a function's world is fixed when it is entered). Checked 2026-11-19: `base` with the session file gives E-5's rows exactly, timings aside.
- **Loading.** The variant's `src/Rules.jl` is included into `Main`, then its `outside.jl` if it has one (code of another module in the same session). Zygote is warmed up on `warm(x) = x + one(x)` at both argument types, as in E-AD-0.
- **The derived program** of `gradient(f, x)` at `T = Tuple{typeof(f), typeof(x)}`: the `_pullback` instances reached from `T` and, per instance, its **piece**:
  - **reached**: `code_typed(_pullback, (Context{false}, T…); optimize = false)` runs Zygote's generator for `T` and infers it; every call to `_pullback` in it, with its inferred argument types, is a reached instance. The walk stops at an instance a hand-written adjoint or a ChainRules rule covers (Zygote calls it, not a generated pullback), at a non-concrete one (a call Julia cannot infer: the program is marked `dynamic`, incomplete, because what runs is decided at run time), and after 2 000 instances (`cut`; never reached here).
  - **piece**, in the order Zygote decides: if dispatch selects a `_pullback` method other than Zygote's generated one, kind `adjoint`: that method and the `ZygoteRules.adjoint` method it calls (where `@adjoint` puts the derivative); else, if `has_chain_rrule` says a rule applies, kind `rule`: the rule method Zygote's check chose; else Zygote's forward generator, kind `ir` (its statements, then the pullback's IR from the backward generator: per block its arguments, statements and branches) or `expr` (what the generator returns when it does not differentiate: a call with an empty pullback, an error). A method is printed as its module, signature and lowered body, followed by the bodies of the closures it creates, recursively (a rule's pullback is such a closure).
  - The generators are called with the session's current world, so they give what Zygote **would** build now, not what it compiled earlier (see `+session`).
- **Texts are process-independent**: closure names are numbered by the session that lowered them (`var"#2849#2850"`) and all become `var"#closure"`; a closure is told apart by its body, printed where it is created. Two runs of all ten variants gave identical output apart from the four timing columns (2026-11-19). At start the script checks that two IRs differing only in what they return print differently.
- **Rule tables**: per table, the number of methods and a SHA-256 over every method's module, signature and lowered body (`table`); and each method whose signature names a function of the package (`rule`, sorted). These are method-table facts: no gradient is taken for them.
- **In-session check** (second argument): after the variant's rows, the file is included into the live module `Rules` (for `base`, `rule_g`'s rule) and the tables and rows are computed again as `base+session`. The rule in `rule_g/src/added.jl` counts its calls; `calls` lines give the count after the rows, after `gradient(g, 0.7)` again, and after the gradient of a closure compiled only after the rule was added.
- **Times**: `ns_first` the first `gradient(f, x)` in the process (Zygote's transformation, Julia compiling, one run); `ns_walk` the walk (inference of each reached instance); `ns_gen` Zygote's own calls once per reached instance (dispatch, the rule check, both generators: `transform`, no printing), after emptying Zygote's decomposition cache, which is keyed by signature and world and would otherwise answer from the first call's work; `ns_cached` the same again on the filled cache.
- **Output lines**: `julia VERSION`; `package NAME VERSION`; `table label name methods digest`; `rule label table module sig body`; `derived label target type instances all|dynamic|cut ns_first ns_walk ns_gen ns_cached gradient`; per instance `instance label target type sig kind piece-digest`; `calls label [what] n`; at the end each piece once, `piece digest text` (text escaped: `\\`, `\n`, `\t`, `\r`).

This is Julia, not Sophia code: it measures Julia. Sophia stays Rust (S-ADR-0004).
