#implementation #julia #experiment

> The Julia side of experiment E-4 (macro expansions as transformation records): each module-level form of a package that calls a macro, replaced by Julia's expansion of it as **source text**, with the inputs the expansion was computed from, whether it is recomputed from those inputs alone, and the methods the text makes when Julia evaluates it in place of the form. Source: `expansions.jl`.
>
> Sources: [[Review 2026-11-19 Codex B-025 (external)]]; Julia ≥ 1.12 (`macroexpand`, quote interpolation, `Method.primary_world`, `Base.get_world_counter`); [[macros]] (the loading, shared with part 5 of [[Julia Conformance]]). code: `expansions.jl`, `src/expansion.rs` ([[expansion]]), `tests/expansions.rs`, `examples/julia_expansions.rs` ([[julia_expansions]])

```sh
# from crates/sophia-ingest/tests/julia-semantics
julia expansions.jl Exp expansions/src > expansions/truth.tsv
julia macros.jl Exp expansions/src | sort > expansions/macros.tsv          # for `faithful`
julia expansions.jl LinearAlgebra <stdlib>/LinearAlgebra/src > expansions-la.tsv   # about 20 s
```

- **Methods** go to the innermost world window they entered the method table in: a record's (the later one on a tie, so an inner record wins), else its form's (record 0, keyed by the form, so a file included into two modules gives two forms).
- **Loading** as `macros.jl`: the package's files are parsed and evaluated form by form, `include("literal.jl")` and `module … end` followed, so a method belongs to the window of world ages it entered the method table in.
- **Records.** Each `@eval ex` (and `@eval M ex`) outside a definition becomes a call that evaluates each `$` splice once (into a local), fills the template from those values as Julia's quote would, records the values (`repr`; a splat `$(xs...)` is one value, the collection) and the filled expression, and evaluates it: one **eval record** per evaluation, so an `@eval` loop gives one record per value. A form that is a macro call without `@eval` is one **macro record**: `macroexpand(M, form; recursive = false)`, one level. If a record's text itself calls `@eval` (a macro that expands to one), those calls become records of their own and the outer record keeps only its other statements, so each definition is in one record. A docstring is dropped and the documented form expanded. A form with a macro call elsewhere (`if … @inline f(x) = 1 end`) is evaluated as written; what it makes is record 0, `rest`.
- **Text.** Hygiene is removed: `esc(x)` is `x`, and in the macro's own scope a name its module binds (and the user's module does not bind to the same object) is qualified (`depwarn` → `Base.depwarn`). The macro's local names, gensyms such as `var"#40#x"` (quoted ones too), are renamed to plain names (`x`, or `x_2` when the record or the module already uses `x`), so a record's text does not depend on what the process expanded before it and holds no name the shared parser refuses; a local could in principle shadow a name of the user's module (not seen so far, and the evaluation would show it). Module-level `begin` and `toplevel` blocks are flattened, line numbers dropped. Julia prints what has no surface syntax as `$(Expr(:meta, :inline))`; parsing back rebuilds every `$(Expr(…))` with literal arguments.
- **Checked by evaluation.** The record's text, not Julia's expression, is parsed and evaluated in place of the form, so the methods listed come from the text (`status ok`). If the text does not parse (`unparsed`) or throws (`failed`), Julia's expression is evaluated instead and the record says so.
- **`stable`**: an eval record's inputs are parsed back and evaluated in the module, the template filled with them, and the result printed again; `yes` if it prints the same. A macro record is expanded a second time and both printed (gensyms renamed, so only their numbers may differ). `no` marks hidden state: a value whose `repr` does not read back (a closure), or a macro whose output depends on more than its call (a counter). It cannot see state that changed **between** two calls (a macro reading a global set between them): each call re-expands the same in its own state. That case shows on Sophia's side as two texts under one input address (`clashes`, [[expansion]]).
- **Costs**: `ns_expand` is the time to make the expression (filling the template; `macroexpand`), `ns_eval` the time to parse and evaluate the text; `bytes` the text's length.
- Output lines: `julia VERSION`; `record file line k kind by module stable status ns_expand ns_eval bytes inputs template text` (module: the module the record was evaluated in, another one than the form's for `@eval M ex`; the template is an eval record's `@eval` argument as written, with its `$`; inputs joined by tabs, then all three escaped: `\\`, `\n`, `\t`, `\r`); then that record's `method file line k owner sig` (sorted) and `binding file line k kind name`. Owners as in [[macros]].
- **Not reproducible across runs in one respect**: the two time columns. Everything else was identical in two runs on LinearAlgebra once methods were sorted (2026-11-19).

This is Julia, not Sophia code: it measures Julia. Sophia stays Rust (S-ADR-0004).
